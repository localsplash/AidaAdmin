# Native PBX administration

AidaAdmin administers native OfficePulse/Asterisk records through its authenticated same-origin backend. Identity owns people, tenant roles, selected tenant and enabled voice-number assignment. OfficePulse owns native PBX configuration and effective routing; AidaAdmin does not write Asterisk SQL or files. Tenant PBX scope, assistant profiles, profile assignments and appearance remain business configuration in PlatformConfig.

## Contract and authorization

The backend introspects the Identity application session on every request. Each PBX handler requires Tenant Admin access (or Super Admin), an enabled exact tenant, and that same selected tenant. Browser `X-Aida-*` headers are stripped; query/body tenant or role overrides are rejected. All browser mutations require the existing CSRF proof and cookie protections.

The customer tenant (`iTenantId`) is authorization and customer identity only. **The PBX routing scope is `{pbxInstanceId, context}`**: OfficePulse's `OFFICEPULSE_INSTANCE_ID` and one Asterisk extension context. AidaAdmin resolves that scope from PlatformConfig (`server/src/admin/pbx-scope.ts`), never from the browser:

- `aida_tbl_TenantProfile.asterisk_context` is the tenant's primary extension context and the default scope; `additional_contexts` (comma-separated) lists further extension contexts it owns; `did_context` names the shared carrier ingress context (for example `from-bandwidth`) whose `extensions` rows hold its managed DID routes. Extension contexts belong to exactly one tenant; a tenant's `did_context` may not equal any of its extension contexts (400). Grammar for every context is `^[a-zA-Z0-9_.-]{1,40}$`.
- Browser PBX routes accept an optional `?context=`. It must be one of the tenant's own contexts, otherwise 403 `context_forbidden` and no OfficePulse call. Without it the primary context is used. A tenant with no primary context gets 409 `pbx_scope_missing` ("Assign this tenant's Asterisk context in Tenants first"); DID routes without a `did_context` get 409 `pbx_scope_missing` ("Assign this tenant's inbound DID context first"). Scope is read from the stored `aida_tbl_TenantProfile` row alone (the session already proved the tenant, so the Identity directory is not consulted per PBX request); when that row cannot be read the request fails with 503 `nocodb_unavailable`, and a missing table answers 503 `platform_config_unavailable` naming the table to upgrade — never an empty scope.
- Every OfficePulse inventory must echo `context` (and `didContext`) and name its `pbxInstanceId`; a missing or mismatched echo is 502 `officepulse_failed`. Browser responses pass `pbxInstanceId`, `context` and the authorized `contexts` list through so the UI can render a selector.
- `GET /admin/pbx/contexts` (Super Admin) proxies OfficePulse's context list for the Tenants form datalist. Listing a context grants nothing; assignment happens in Tenants.

The server-only `OFFICEPULSE_API_BASE_URL` points to the admitted private OfficePulse API; the previous `OFFICEPULSE_PROVISIONING_BASE_URL` setting remains a compatibility alias. Never place the private URL or PBX credentials in Vite/browser configuration. Native requests have a ten-second timeout, forbid redirects, URL-encode path components (especially E.164 `+` as `%2B`), and carry the server correlation ID.

| Same-origin path under `/admin/tenants/:tenantId` (`?context=X` optional) | Method     | OfficePulse path under `/v1/admin/pbx`                                                   |
| ------------------------------------------------------------------------- | ---------- | ---------------------------------------------------------------------------------------- |
| `/extensions`                                                             | GET/POST   | `/extensions?context=X`                                                                  |
| `/extensions/:extension`                                                  | DELETE     | `/extensions/:extension?context=X`                                                       |
| `/queues`                                                                 | GET/POST   | `/queues?context=X`                                                                      |
| `/queues/:queue`                                                          | DELETE     | `/queues/:queue?context=X`                                                               |
| `/queues/:queue/members/:extension`                                       | PUT/DELETE | `/queues/:queue/extensions/:extension?context=X`                                         |
| `/did-routes`                                                             | GET        | `/dids?context=X&didContext=Y&authorizedDid=...` for the current Identity tenant Numbers |
| `/did-routes/:did`                                                        | PUT/DELETE | `/dids/:did?context=X&didContext=Y&authorizedDid=...` after rechecking Identity          |
| `/admin/pbx/contexts` (no tenant; Super Admin)                            | GET        | `/contexts`                                                                              |

Request schemas and native response types are in `server/src/officepulse/pbx-contract.ts`. Shared OfficePulse OpenAPI and HTTP fixtures live in `server/test/fixtures`; changes must be copied verbatim from the companion repository and tested on both sides. Local validation returns 400, upstream validation 422, missing records 404, conflict 409, unavailable dependencies 503, and unrecognized upstream failures 502. Responses contain safe copy and a correlation ID, never raw upstream bodies/SQL. Audits record actor, tenant, action, object reference, correlation ID, status and outcome; create responses and credentials never enter audit payloads.

## Assistant profile assignments

Which assistant answers a call is a persisted PlatformConfig record, `aida_tbl_ProfileAssignment` (logical `profile_assignment`): `pbx_instance_id`, `context`, `did` (E.164, or empty for the context default), `profile_id`, `enabled`, plus the owning `iTenantId`. The key `(pbx_instance_id, context, did)` is unique. OfficePulse reads the table on its existing refresh cadence and resolves a call in scope `{pbxInstanceId, context}` dialled at `did` to the exact-DID row, else the context default, else the caller stays on the PBX queue. No operator edits environment JSON to select a profile.

| Same-origin path under `/admin/tenants/:tenantId` | Method | Behaviour                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/profile-assignments`                            | GET    | `{pbxInstanceId, contexts, assignments:[{id, pbxInstanceId, context, did, profileId, enabled, revision}]}`; `pbxInstanceId` is null while OfficePulse is unreachable                                                                                                                                                                       |
| `/profile-assignments`                            | PUT    | Body `{context, did: string\|null, profileId, enabled?}`. `context` must be one of the tenant's contexts (403), `did` must be one of its enabled Identity voice numbers or null (400), the profile one of its enabled profiles (404/400); `pbxInstanceId` is pinned from OfficePulse readiness (503 `officepulse_unavailable` when absent) |
| `/profile-assignments/:id`                        | DELETE | Removes the tenant's own row (404 otherwise)                                                                                                                                                                                                                                                                                               |

Same guard as the PBX routes: Tenant Admin or Super Admin with the tenant selected. Audit actions are `profile_assignment.save` and `profile_assignment.delete`; payloads carry ids, never prompts.

## Screens and lifecycle

- The tenant banner names the selected tenant's primary PBX context. Extensions, Queues and Numbers show the PBX instance and the context they act in, with a context selector when the tenant owns more than one.
- Tenants (Super Admin) sets the primary Asterisk context, additional contexts and the inbound DID context; the inputs suggest the instance's known contexts from `/admin/pbx/contexts`.
- Extensions list native IDs, dialable numbers, caller ID, context and activation state. Create discloses SIP username/secret once. Dismissal or tenant navigation destroys that disclosure state; inventory/retries cannot reopen it, and no browser storage is used. Losing the secret requires a future rotation capability. Contexts and formatted caller IDs are constrained to the installed 40-character Asterisk columns. OfficePulse reports `managed` for endpoints that carry its Dial route in the context (new ids are `<extension>-<context>`; legacy `<extension>-tN` bundles remain managed through their own route); imported endpoints remain operator managed. Delete confirmation explains removal of saved queue memberships. Edit, rotation and handset-enrollment controls are retired.
- Queues replace Ring Groups. Friendly names become native `<context>.<slug>` IDs; ownership is the versioned marker row OfficePulse keeps in the owning context. Membership edits compute minimal PUT/DELETE differences and retain a partial-success baseline for retry. Penalty is 0–100; paused is Boolean. Imported member interfaces remain read-only. A referenced-queue conflict links to Numbers.
- Numbers is the canonical tenant screen: the Add Number / DID form creates a globally unique assignment in Identity, and every Identity assignment appears once, including disabled numbers. AidaAdmin sends the current Identity assignments to OfficePulse on every managed-DID request, so a new Number appears as unconfigured without a per-number environment edit. Each card attaches its PBX state: configured, unconfigured, manual/operator managed (including routes whose queue another context owns), PBX scope missing, or unavailable. Each card also carries an "Assistant profile" selector for the DID in the selected context; "Use context default" removes the DID-specific row. Identity loads independently of DID/queue inventory; OfficePulse failures retain Numbers and metadata editing while disabling routing actions. A single number opens its routing editor automatically without submitting defaults; multiple numbers have independent expandable editors and no global DID selector. Routes may be created only for enabled Identity voice numbers; manual and foreign routes cannot be adopted. The form requires an owned queue, 1–12 rings, and optionally local business hours, weekdays and a valid IANA timezone. The queue timeout is approximately five seconds per ring and the returned value is shown. LiveKit is the only destination provider; an advanced E.164 destination override defaults to the DID. Assistant profiles are not sent as PBX destinations.
- Profiles keeps the profile editor and adds "Default profile for context <X>" for each of the tenant's contexts.

During scheduled hours the queue rings before LiveKit; outside hours callers go directly to LiveKit. Without a schedule, the queue is always open before LiveKit. Disabling a managed DID route deletes PBX routing only; it does not disable/reassign the Identity number, carrier, messaging or assistant profile assignment.

Every mutation disables duplicate submits. Recoverable failures preserve inputs. Successful writes refresh affected inventory. Tenant or context changes unmount forms/disclosures and ignore late responses. Controls have accessible labels, fieldsets and live errors/status; destructive operations require explicit browser confirmation.

`committed` means only that the OfficePulse database transaction committed. `active` may be displayed only if OfficePulse supplies verified effective state; this OfficePulse implementation never returns active. Native inventory can report activation unknown. A static DID in operator-owned `extensions.conf` can still win over Realtime rows, and PJSIP/queue caches can lag committed SQL. A database success must not be presented as proof of an active telephone route.

## Migrating from tenant maps

OfficePulse no longer reads `PBX_INVENTORY_TENANTS_JSON` or `AGENT_PROFILE_IDS_JSON`; it refuses to start while either is set. Each former entry moves here:

1. `PBX_INVENTORY_TENANTS_JSON` `"<iTenantId>": {"contexts": [...], "didContext": "...", "queueNames": [...]}` → in Tenants set the tenant's Asterisk context (first entry), additional contexts (the rest) and inbound DID context. For every former `queueNames` entry run OfficePulse's `npm run pbx:adopt-queue -- <context> <queue>` and apply the reviewed marker statement it prints; after that the queue appears under its owning context.
2. `AGENT_PROFILE_IDS_JSON` `"<iTenantId>": "<profileId>"` → in Profiles choose that profile as "Default profile for context <X>" for the tenant's context(s); per-number exceptions are set in Numbers.

Run `npm run nocodb -w server -- upgrade` first: it adds `additional_contexts` and `did_context` to `aida_tbl_TenantProfile` and creates `aida_tbl_ProfileAssignment` additively.

## Deployment, cleanup and rollback

1. Deploy the companion OfficePulse contract and least-privilege grants, then assign each tenant's contexts in Tenants and adopt legacy queues. An operator must install the shared `aida-managed-did-v1` include and one generic Realtime lookup on the reviewed ingress context before routing calls. Managed DID destinations, schedules, queues and fallbacks live in Realtime data rows; remove the corresponding DID-specific static route after its managed rows exist.
2. Deploy this backend with server-only OfficePulse URL, central Identity session/directory access and audit persistence. Verify a Tenant Admin and Super Admin across two tenants (and one multi-context tenant) before exposing mutations.
3. Expose the UI after inventory and managed-DID readback succeed. `provisioningEnabled=false` keeps inventory read-only. An unavailable OfficePulse endpoint is not treated as empty inventory.

Legacy extension/ring-group/DID routes, payload builders and retry controls are removed. Runtime provisioning/fallback views and SQL accessors are retired. The former NocoDB PBX repositories and schema definitions are removed, preserving the existing DEV cleanup. Follow [DEV_RESET.md](DEV_RESET.md) for operator-managed removal of obsolete data. No data deletion or migration into native routing is automatic.

The disposable DEV cleanup removes `aida_tbl_Extension`, `aida_tbl_RingGroup`, `aida_tbl_RingGroupMember`, `aida_tbl_DidRoute`, and obsolete handset/projection fields using the exact scope in the reset runbook. Preserve `aida_tbl_AssistantProfile`, `aida_tbl_ProfileAssignment`, tenant business metadata, appearance, Identity assignments and audit history. Legacy records must never be silently replayed into PBX configuration.

Rollback hides/disables mutation UI or disables the OfficePulse writer, preserving existing PBX objects. A frontend/backend rollback must retain the compatible native API contract; never automatically reinstate the legacy NocoDB synchronization workflow. Restoring PBX routes is an independent operator-owned change using reviewed exports, not an AidaAdmin migration.

## Validation and limits

Run `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, then `npm run test:e2e`. The native browser tests use the real BFF authorization/session/CSRF handlers against disposable Identity and PBX fakes; they exercise create/disclosure in two contexts of one tenant (overlapping extension numbers), context selection and refusal (`context_forbidden` for another tenant's context and for the ingress context), queues/members, schedule/readback, a context-default and a DID profile assignment pinned to the PBX instance, conflicts, deletion, tenant restriction, Super Admin switching with the banner's PBX context, and the scope-missing states (no ingress context; no profile row). Unit tests additionally capture logs/audits for SIP-secret regression and check exact native method/path/body/error contracts against the shared fixtures.

These tests do not establish live Identity authentication, carrier calling, effective Asterisk reload/cache state, recording behavior or static-route precedence. External release evidence must cover overlapping extension numbers for two contexts, native queue membership, during/outside-hours calls, timeout-to-LiveKit, answered queue without AI, secret handling, cross-tenant and cross-context denial, profile resolution per context/DID and orphan-free deletion while Identity numbers remain assigned. Follow the companion OfficePulse runbook before calling the POC operationally complete.
